workflow/RiboSeq_TE.smk (Phase 2 debugging, 2026-10-15)
    - real design gap: CONTRASTS' group1/group2 were used directly as the
      fastq-prefix for BOTH runs' featureCounts paths, but the two
      projects are never guaranteed to share one (confirmed on real data:
      "ribo_untr_a" vs. "mrna_untr_a" for the same nickname). Now
      translated per-project via load_nickname_map() against each
      project's own RIBO_SAMPLES_YAML/RNA_SAMPLES_YAML.
    - te_analysis rule's memory floor bumped 2->16GB (see te_analysis.R
      entry below for why)

workflow/scripts/te_analysis.R (Phase 2 debugging, 2026-10-15 -- 5 real
bugs found running the untested first draft against real anota2seq/xtail,
all on the real GSE65778_untr_tm_TE test run)
    - purrr::reduce() shadowed by IRanges' S4 generic once anota2seq loads
      its Bioconductor stack ("unable to find an inherited method for
      function 'reduce' for signature x = 'list'") -- qualified as
      purrr::reduce explicitly
    - anota2seq hard-requires >=3 replicates per group (real test data has
      2) and errors rather than degrading -- now skipped gracefully with
      NA placeholder columns (apvEff/apvRvmPAdj) when a group is too
      small, falling through to xtail alone
    - xtail's memory need doesn't scale with featureCounts file size at
      all (driven by its own permutation-based significance testing) --
      OOM-killed at ~1.3GB against the old 2GB floor
    - resultsTable(xt, log2FCs=TRUE) returns a matrix, not a data.frame --
      rownames_to_column("ID") failed with "is.data.frame(df) is not
      TRUE" -- wrapped in as.data.frame() first
    - the 4-quadrant plot's aes() referenced log2FC_mRNA/log2FC_RPF, but
      xtail's real resultsTable() output names them mRNA_log2FC/
      RPF_log2FC (reversed word order) -- fixed to match
